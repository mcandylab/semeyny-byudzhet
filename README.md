# Семейный бюджет

Приложение на Nuxt 4. Для локального запуска нужны Node.js 22.22.3+ или 24.15.0+ из LTS-линеек и npm.

```sh
npm ci
npm run dev
```

Подключение к существующему Supabase задаётся в локальном `.env`. В новом клоне скопируйте `.env.example` в `.env` и укажите URL того же проекта Supabase и его ключ `publishable`. Nuxt читает эти значения на сервере. Для общего бюджета используется прежняя таблица `budget_snapshots`, поэтому SQL-миграции не нужны.

## Публикация

```sh
npm run build
npm start
```

На хостинге задайте `NUXT_SUPABASE_URL` и `NUXT_SUPABASE_KEY` в окружении или в `.env` рядом с `package.json`. Для доступа с других устройств используйте HTTPS, который нужен браузеру для расшифровки бюджета.

Текущий GitHub Pages обслуживает статические файлы. Для новой версии нужен хостинг с Node.js и маршрутом `/api/budget`. Если сайт открывается из подпапки, задайте `NUXT_APP_BASE_URL` с завершающим слешем, например `/semeyny-byudzhet/`, при сборке и запуске.

При смене адреса сохраните всё после `#` в семейных ссылках. В этой части находится ключ расшифровки, а в некоторых старых ссылках также начальные данные. Для сохранения старых ссылок нужен переход со старого адреса на новый с тем же фрагментом. Кэш браузера привязан к исходному адресу сайта. Если на устройстве есть ещё не отправленные изменения, перед сменой домена синхронизируйте их или скачайте резервную копию.

## Новый бэкенд: PocketBase

Новый бэкенд работает локально на [PocketBase](https://pocketbase.io/) 0.40.6. С ним работает мобильное приложение на `/app`. Страница `/` пока остаётся прежней и хранит данные в Supabase.

```sh
npm run pb:install   # скачать PocketBase и проверить контрольную сумму
npm run pb:serve     # http://127.0.0.1:8090, админка на /_/
npm run dev          # во втором терминале; приложение на http://localhost:3000/app
```

Чтобы открыть приложение с телефона в той же сети Wi-Fi, запустите `npm run dev -- --host` и откройте `http://<адрес компьютера>:3000/app`. В режиме разработки Nuxt пересылает запросы с `/pb` на PocketBase. Адрес PocketBase меняется переменной `POCKETBASE_URL`. В продакшене адрес, по которому браузер обращается к PocketBase, задаётся в `NUXT_PUBLIC_POCKETBASE_URL`.

### Мобильное приложение

Экраны лежат в `app/components/mobile`, данные приходят из `app/composables/useFamilyBudget.js`. Хранилище загружает записи семьи и подписывается на изменения PocketBase, поэтому правка на одном телефоне сразу видна на другом. После потери связи, а также когда вкладка снова становится видимой, данные загружаются заново. Итоги считает прежняя `calculate()` из `app/utils/budget.js`, поэтому суммы совпадают со старым приложением.

Галерея `/mobile` и прототип `/mobile/app` показывают те же компоненты на демо-данных из `app/utils/family-demo.js`. Они работают без сервера и ничего не сохраняют.

В git хранятся `pocketbase/pb_migrations` со схемой и `pocketbase/pb_hooks` с серверными правилами и командами. Бинарный файл, база `pocketbase/pb_data` и расшифрованные выгрузки `pocketbase/import` остаются только на компьютере.

### Схема

| Коллекция | Что хранит |
| --- | --- |
| `households` | Семья: зарплата за месяц, процент десятины, комментарий по кредитам |
| `users` | Участники: логин, пароль, имя, семья, роль `owner` (мастер-аккаунт, один) или `member` |
| `invites` | Одноразовые коды приглашения от мастер-аккаунта, действуют 72 часа |
| `categories` | Справочник из 10 категорий |
| `expenses` | Регулярные расходы с выплатой 5-го или 20-го и категорией |
| `expense_payments` | Отметки «оплачено»: одна запись на расход и месяц |
| `envelopes` | Конверты с остатком. Конверт с операциями не удаляется, а архивируется |
| `operations` | Покупки и пополнения конвертов: сумма, дни, дата, автор и название конверта на момент записи |
| `goals` | Цели: сумма, отложено, план на месяц, срок, выплата, закрыта ли |
| `workday_overrides` | Число рабочих дней, исправленное вручную для месяца |

Правила API пускают только участников той же семьи. Даты без времени (`operations.date`, `goals.due_date`) хранятся как полночь UTC. Для одновременного изменения нескольких записей включён `/api/batch`.

Операции меняют остаток конверта, поэтому напрямую через коллекцию их не создают и не удаляют. Для этого есть два маршрута. `POST /api/family/operations` записывает покупку или пополнение, а `DELETE /api/family/operations/{id}` отменяет операцию. Сервер сохраняет операцию и новый остаток в одной транзакции и не даёт потратить больше, чем лежит в конверте.

### Вход без email

Вход выполняется по логину и паролю, письма не отправляются.

```sh
npm run pb -- family:owner <логин> [Имя]   # мастер-аккаунт; пароль выводится один раз
npm run pb -- family:invite [часы]         # код приглашения, например K7P4-9QXM
npm run pb -- family:password <логин>      # новый пароль вместо восстановления по почте
```

Чтобы задать пароль самостоятельно, передайте его в `FAMILY_PASSWORD`. Новый участник присоединяется запросом `POST /api/family/join` с полями `{ code, username, password, name }` и сразу получает токен. Не больше 5 попыток в минуту. Чтобы открыть админку PocketBase, создайте администратора командой `npm run pb -- superuser upsert <email> <пароль>`. Email здесь служит только логином администратора.

### Перенос из Supabase

```sh
npm run legacy:migrate              # первый перенос
npm run legacy:migrate -- --replace # повторный перед переходом: записи бюджета заменятся, участники останутся
```

Скрипт только читает Supabase и расшифровывает бюджет ключом из `LEGACY_BUDGET_LINK` в `.env`. Затем он переносит записи в одной транзакции, выгружает их обратно в формате резервной копии старого приложения и сравнивает каждое поле и итоги `calculate()` с исходными данными. Выгрузка `pocketbase/import/pocketbase-export.json` открывается в старом приложении через «Восстановить из файла».
