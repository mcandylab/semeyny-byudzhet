# Семейный бюджет

Мобильное приложение для общего семейного бюджета: Nuxt 4 и [PocketBase](https://pocketbase.io/) 0.40.6. Для запуска нужны Node.js 22.22.3+ или 24.15.0+ из LTS-линеек и npm.

```sh
npm ci
npm run pb:install   # скачать PocketBase и проверить контрольную сумму
npm run pb:serve     # http://127.0.0.1:8090, админка на /_/
npm run dev          # во втором терминале; приложение на http://localhost:3000
```

Рабочая база живёт в кластере (см. «Публикация»). Локальная `pocketbase/pb_data` — снимок на момент переезда, для разработки берите копию.

Чтобы открыть приложение с телефона в той же сети Wi-Fi, запустите `npm run dev -- --host` и откройте `http://<адрес компьютера>:3000`. В режиме разработки Nuxt пересылает запросы `/api` в PocketBase, как в продакшене, где приложение и API на одном домене. Адрес PocketBase меняется переменной `POCKETBASE_URL`.

## Публикация

Приложение работает на https://money.mcandylab.ru в домашнем кластере k0s, отдельно от платформы nodbox: namespace `money`, без gVisor. Манифесты лежат в `deploy/k8s`.

```sh
npm run deploy:k8s   # собрать статику, обновить ConfigMap и манифесты, перезапустить под при изменениях
```

- **PocketBase.** Работает в StatefulSet `pocketbase` с одним подом и томом `local-path` на 5 ГБ, база лежит в `/pb/data`. Init-контейнер скачивает PocketBase с GitHub, сверяет SHA-256 из манифеста и хранит архив на томе. Статика, `pb_migrations` и `pb_hooks` приезжают в ConfigMap `money-app`. PocketBase сам отдаёт статику, поэтому браузер обращается к API на том же домене.
- **Вход снаружи.** Роутер пробрасывает публичные 80 и 443 на Kourier, общий шлюз кластера. Для домена создан свой KIngress `money`. На публичном домене админка `/_/` и вход суперпользователя закрыты хуком, HTTP перенаправляется на HTTPS. Админку открывает команда `kubectl --context k0s-home -n money port-forward pod/pocketbase-0 8090` и адрес http://127.0.0.1:8090/_/.
- **Сертификат.** Let's Encrypt выдаёт его через свой Issuer в namespace `money` с проверкой HTTP-01. Путь `/.well-known/acme-challenge/` ведёт на решатель cert-manager через сервис ExternalName. Иначе net-kourier перестаёт обновлять маршрут, пока у решателя нет пода, и после продления остался бы старый сертификат. Продление автоматическое.
- **Данные.** `sh scripts/k8s-restore-data.sh <папка pb_data>` заменяет базу пода локальной копией. Перед этим PocketBase должен быть остановлен с обеих сторон. Том лежит на диске ноды `k0s-worker-2`, поэтому включите в админке PocketBase резервные копии по расписанию, лучше во внешнее S3.

## Приложение

Экраны лежат в `app/components/mobile`, данные приходят из `app/composables/useFamilyBudget.js`. Хранилище загружает записи семьи и подписывается на изменения PocketBase, поэтому правка на одном телефоне сразу видна на другом. После потери связи, а также когда вкладка снова становится видимой, данные загружаются заново. Итоги считает `calculate()` из `app/utils/budget.js`, перенесённая из первой версии приложения без изменений.

Галерея `/mobile` и прототип `/mobile/app` показывают те же компоненты на демо-данных из `app/utils/family-demo.js`. Они работают без сервера и ничего не сохраняют.

## Бэкенд: PocketBase

В git хранятся `pocketbase/pb_migrations` со схемой и `pocketbase/pb_hooks` с серверными правилами и командами. Бинарный файл, база `pocketbase/pb_data` и расшифрованные выгрузки `pocketbase/import` остаются только на компьютере.

### Схема

| Коллекция | Что хранит |
| --- | --- |
| `households` | Семья: зарплата за месяц, процент десятины, комментарий по кредитам |
| `users` | Участники: логин, пароль, имя, семья, роль `owner` (мастер-аккаунт, один) или `member` |
| `invites` | Одноразовые коды приглашения от мастер-аккаунта, действуют 72 часа |
| `categories` | Справочник из 10 категорий |
| `expenses` | Регулярные расходы с выплатой 5-го или 20-го и категорией |
| `expense_payments` | Отметки «оплачено»: одна запись на расход и месяц |
| `envelopes` | Конверты с остатком. Конверт с операциями не удаляется, а архивируется |
| `operations` | Покупки и пополнения конвертов: сумма, дни, дата, автор и название конверта на момент записи |
| `goals` | Цели: сумма, отложено, план на месяц, срок, выплата, закрыта ли |
| `workday_overrides` | Число рабочих дней, исправленное вручную для месяца |

Правила API пускают только участников той же семьи. Даты без времени (`operations.date`, `goals.due_date`) хранятся как полночь UTC. Для одновременного изменения нескольких записей включён `/api/batch`.

Операции меняют остаток конверта, поэтому напрямую через коллекцию их не создают и не удаляют. Для этого есть два маршрута. `POST /api/family/operations` записывает покупку или пополнение, а `DELETE /api/family/operations/{id}` отменяет операцию. Сервер сохраняет операцию и новый остаток в одной транзакции и не даёт потратить больше, чем лежит в конверте.

### Вход без email

Вход выполняется по логину и паролю, письма не отправляются.

```sh
npm run pb -- family:owner <логин> [Имя]   # мастер-аккаунт; пароль выводится один раз
npm run pb -- family:invite [часы]         # код приглашения, например K7P4-9QXM
npm run pb -- family:password <логин>      # новый пароль вместо восстановления по почте
```

Чтобы задать пароль самостоятельно, передайте его в `FAMILY_PASSWORD`. Новый участник присоединяется запросом `POST /api/family/join` с полями `{ code, username, password, name }` и сразу получает токен. Не больше 5 попыток в минуту. Чтобы открыть админку PocketBase, создайте администратора командой `npm run pb -- superuser upsert <email> <пароль>`. Email здесь служит только логином администратора.

### Перенос из Supabase

```sh
npm run legacy:migrate              # первый перенос
npm run legacy:migrate -- --replace # повторный перед переходом: записи бюджета заменятся, участники останутся
npm run legacy:sync:k8s             # то же для базы в кластере
```

Первая версия приложения хранила бюджет в зашифрованной таблице Supabase `budget_snapshots`. Скопируйте `.env.example` в `.env` и укажите URL проекта Supabase, ключ `publishable` и семейную ссылку. Скрипт только читает Supabase и расшифровывает бюджет ключом из `LEGACY_BUDGET_LINK`. Затем он переносит записи в одной транзакции, выгружает их обратно в формате резервной копии старого приложения и сравнивает каждое поле и итоги `calculate()` с исходными данными. Выгрузка `pocketbase/import/pocketbase-export.json` открывается в первой версии приложения через «Восстановить из файла».
